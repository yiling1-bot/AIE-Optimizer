# 第十一轮：完整程序 SSA、组合生成与跨应用复用

日期：2026-10-18。工作目录为独立项目 `AIE-Optimizer`。本轮目标是解除
两层整程序准入限制，并为通用优化建立实际可运行的路径。ORCA 保留为
应用案例；通用性通过不同计算和图结构的同一引擎复用检查。

本文保留第十一轮的实现与验证记录。后续可注册 MMUL、周期采集和限域
留出选择的进展见 [第十二轮报告](microkernels-cost-v12.zh-CN.md)。

## 已落地的接口

```text
C++ / MLIR 源导入
  → 完整张量 SSA + 源参数/结果绑定
  → 算子规则重放生成语义变体
  → 图分区 × 标量融合 × 核部署 × 矩阵循环次序
  → 完整代码 / 类型化 ADF 连接 / 成本请求
  → 原源码参考 + 主机执行 / 原生编译仿真
```

`program_ir.py` 使用现有导入张量 SSA，逐节点重放类型、范围、初始化和
依赖。输入/输出个数和层数由程序决定。C++ 的输出参数会占用源参数位置，
因此提供显式新 SSA ID 到源输入 ID 的映射，保留源 restrict/别名条件；
不会因规范化 ID 而错接权重或丢弃结果。

`program_rules.py` 注册匹配、守卫、改写、版本和成立理由。首批通用规则：

| 规则 | 变换 | 正确性条件 |
| --- | --- | --- |
| `tensor.matmul.partition_k` | 收缩维分片，部分矩阵乘法再求和 | 在声明的模整数环中求和；原初始化只计入一次；保持量化位置 |
| `tensor.matmul.partition_m` | 输出行域分片，独立计算后拼接 | 输出域不交叠、完整覆盖，初始化同域切片，保持结果顺序 |

规则作用于任意匹配节点，可以继续组合。测试额外注册了一条加法交换规则，
不增加新的整程序 mode，即可进入同一搜索、生成和主机检查。这里的等价
依据仍是可信规则实现和结构重放，有限数值见证仅作为补充。

## 组合生成

`program_planner.py` 组合完整图变体、连续拓扑区域、单使用者内联和
`ijk/ikj` 矩阵循环顺序。区域可以复用一个核，也可以划分为多个物理核。
共享生产者跨区域时物化并连接；区域内合法标量表达式可内联，保持每个
原整数操作的截断和模语义。矩阵乘法不作为可递归内联的标量节点。

生成代码及物理连接相同的提案合并并保留对应关系；没有矩阵乘法的图
不会枚举无效的矩阵循环参数。参考方案和成本未知的候选保留。

`program_backend.py` 支持静态正维度、rank ≤ 4、i8/i16/i32：常量、splat、
加乘、带符号 min/max、扩展/截断、矩阵乘法及初始化、转置、切片和拼接。
新算子必须增加类型语义与 lowering；无法解释的算子显式拒绝。

接口按完整源签名生成独立输入/结果 PLIO，以逻辑行主序交付，每帧按
16 字节补齐。填充不参与逻辑计算，输出填充清零并纳入原生输出检查。
原 ADF 通信接口尚未恢复。内存准入使用局部临时数组、栈和双缓冲的
保守总量；实际 bank、程序存储及放置仍由编译器验证。

这是通用标量 baseline，尚未接入原两层路径的高性能 MMUL lowering。
原路径继续保留，不能据此声称核内性能差距已经解决。

## 成本接口

`program_costs.py` 产生完整候选的组件签名，包含算子/类型/属性、融合与
物化选择、循环次序、端口与位置、生成计算体摘要和工具上下文。
它复用 Analyzer 的严格成本注册表、相关成本族选择和时钟因果图。
匹配成本后可进行条件排序与延迟—核数前沿；缺成本时不返回零延迟，
候选保持待测。不同条件与成本场景分别排序。

当前适配器只描述**首帧、源输入在零时刻可用、声明独立逻辑链路**的
条件图。真实 DMA 通道、共享别名、槽位复用、仲裁及跨帧流水未恢复。
源码摘要不是已编译组件证据；该接口不自动继承既有阶段模型的硬件覆盖，
更不能自动套用旧两层仿真成本。原生结果保持 `analyzer_prediction: null`。

## 验证范围

`tools/program_reuse_witness.py` 通过同一 API 和预算运行四类公开合成输入：

| 程序 | 超出原两层准入的能力 | 独立参考 |
| --- | --- | --- |
| 三层量化矩阵链 | 任意图层数、四个输入 | 原 MLIR 标量区域执行 |
| 整数三抽头 FIR | rank 1、i16、切片与算术组合 | 原 MLIR；语义为逐操作模 i16 |
| 分支/转置/切片/拼接 | 共享生产者、两个输出、非微块形状 | 原 MLIR 标量区域执行 |
| C++ 残差与双输出 | i16 输入、i32 输出、完整源签名 | 独立 g++ 编译执行原源码 |

另有四层图、rank 3 访问变换、混合类型多输出、非零矩阵初始化、极值
溢出、源参数位置交错、规则组合、非法候选拒绝和成本失配测试。
主机执行检查的是完整生成计算 DAG，不能替代 ADF 协议和硬件计时验证。

本轮完整回归 **170/170 通过、无跳过**，较原 146 项新增 24 项。
去除无效循环参数及重复生成实现后，四类应用保留 **18 个软件生成工程、
72 帧、1472 个逻辑输出检查**；每个应用最多保留 24 个计划，不能将候选
数或通过的帧数当成独立性能样本。七步 CLI 导入/规划/生成/CPU/成本请求
见证通过；空成本目录返回 `needs_measurement`。

### 原生验证

在 beiyou 的隔离目录运行三个有超时限制的案例，均通过 Vitis 2024.2
编译、实际映射检查及 AIE-ML 仿真。AIE 1.25 GHz、PLIO 128 bit / 200 MHz，
每案例 4 帧，共 256 个逻辑输出精确一致；补齐字段也检查为零。

| 案例 | 实际核数 | 首帧全部输出完成 / ns | 逻辑输出检查 |
| --- | ---: | ---: | ---: |
| 三层矩阵链，4×8 激活、8×8 权重 | 1 | 3065 | 128 |
| 3×4 分支图、转置/拼接两个结果 | 2 | 1195 | 96 |
| 10 元素 i16 输入、8 元素 FIR 输出 | 1 | 745 | 32 |

计时从仿真原点开始，包含启动；三个应用不能相互构成 Pareto 前沿，也
不能与旧 32×32 两层结果比较优化幅度。每个案例只有一次编译/仿真运行，
没有同预算性能基线、重复运行或板卡结果；本轮证明可部署与数值闭环。

原生任务使用上传时的冻结源码。随后仅完善搜索去重和无效参数处理，
导致规划器指纹变化。保存原生包及其方案 ID，并独立核对最终对应方案的
所有编译输入、输入数据、参考输出逐字节相同，部署字段、实际映射和
每个输出值/时间戳也一致；该复核不增加原生运行次数、不校准成本。
证据位于本地 `output/research/AIE-Optimizer/phase11/`，包括
`tests-checkpoint.json`、`software-witness/report.json`、`cli-witness/report.json`、
`native-final-source-audit.json`、上传包与原生证据包及其完整 SHA256 目录。

## 尚未完成

- 新通用 SSA 与既有 `Expr`/e-graph 尚未完全统一；当前语义变体为有界显式图。
- 分区仍限定连续拓扑区间；任意任务集合、重算、跨算子流水和时间复用待扩展。
- 算子 lowering 仍在一个模块中；高性能可注册微内核及其成本域待补齐。
- 动态控制流、memref/指针别名、AIE API、浮点、近似数值契约未覆盖。
- 全阶段硬件校准、留出排名、完整 ORCA 与板卡验证未完成。
- 跨应用证据仍为合成小图；不构成全领域通用性或性能优越性证明。

下一阶段应把核内 lowering 变为可注册实现族，先复用 MMUL 的实测和
生成能力，再将真实成本与执行边界绑定到这些实现族，扩大图抽取能力。
