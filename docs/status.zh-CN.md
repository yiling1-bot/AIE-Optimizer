## 验证证据的层次

本仓库提供可复现的源代码与 224 项软件回归测试。可选前端与主机
编译器齐备时可运行完整套件。私有实验归档与 SDK 不随仓库发布。

应分别记录：

- 原源码与导入 IR 的数值一致性。
- 导入契约与生成计算代码的数值一致性。
- AIE 编译映射、实际 buffer/lock/resource 与生成计划的一致性。
- 原生仿真输出和明确边界下的延迟。
- 成本模型对未用于校准的候选的排名质量。

前一层成功不能替代后一层证据。CPU 数值通过不证明 ADF 活性，
静态 AST 调用计数不等于动态周期，条件阶段排序不等于板卡收益。

## 接下来的实现顺序

1. 补 AIE1 目标生成与语义/编译绑定，开放同工作量跨编译、跨核数
   比较；先用已覆盖的私有核/window/cascade 机制形成真实闭环。
2. 在已统一的多输出 SSA/e-graph 上增加克隆/重算实例、布局状态和
   更广分区，并完善增量匹配与预算分配。
3. 扩展共享/复制及必要的 Analyzer 执行原语，覆盖 owner-limited DMA、
   fanout/join、共核和层间窗口；冻结新成本后做留出排名验证。
4. 增加真实计算家族和应用，检验同一引擎复用与性能收益；完整 ORCA、
   系统文献覆盖和板卡分别持续验收。

AIE-ML 路线同时保留标量非线性诊断、独立锁/DMA/槽位校准及更多形状
留出的缺口；现有 AIE1 评价可先驱动其已支持目标的优化研究。

优先在相同核数与条件下寻找延迟收益，同时保留更高或更低核数
带来更好权衡的方案。
