## 验证证据的层次

本仓库提供可复现的源代码与 146 项软件回归测试。可选前端与主机
编译器齐备时可运行完整套件。私有实验归档与 SDK 不随仓库发布。

应分别记录：

- 原源码与导入 IR 的数值一致性。
- 导入契约与生成计算代码的数值一致性。
- AIE 编译映射、实际 buffer/lock/resource 与生成计划的一致性。
- 原生仿真输出和明确边界下的延迟。
- 成本模型对未用于校准的候选的排名质量。

前一层成功不能替代后一层证据。CPU 数值通过不证明 ADF 活性，
静态 AST 调用计数不等于动态周期，条件阶段排序不等于板卡收益。

## 接下来的实现顺序

1. 从已生成的 kernel 建立带形状、执行规则、编译器和实现指纹的
   隔离周期证据，解释核内代码生成性能差距。
2. 从实际编译资源恢复锁、DMA、共享缓冲和槽位，校准传输、复制、
   同步与启动阶段，保留无法覆盖的候选。
3. 在校准集之外选择候选，评价延迟误差、排序与搜索预算下找到的
   已验证前沿，检查排名是否足够指导抽取。
4. 扩展代码导入和可执行机制，再覆盖完整应用和板卡。

优先在相同核数与条件下寻找延迟收益，同时保留更高或更低核数
带来更好权衡的方案。
